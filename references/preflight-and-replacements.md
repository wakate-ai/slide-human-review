# 作る前の設計と「やめること → 代わりにすること」

## 1. 設計宣言（スライドを作る・直す前に書く）

| 項目 | 書くこと |
|---|---|
| 資料の種類 | 経営会議の決裁、営業提案、IR、会社紹介、技術説明、研修、報告、登壇など |
| 読み手と目的 | 誰が、何を理解・判断・行動するのか |
| 結論・決めてほしいこと | 決める対象、責任者、予算、期限、判断の根拠（あてはまるとき） |
| 時間・量 | 持ち時間とパートごとの配分、またはページ数の目安（`content-first.md` の手順1） |
| 話さないこと | 今回載せない話（`content-first.md` の手順2） |
| 話の流れ | 問い → 根拠 → 選択肢・施策 → 確かめ方 → お願いしたいこと。章を機械的に増やさない |
| 色の役割 | ベースとアクセントの2色が基本。背景・本文・補助・強調・注意それぞれの用途。強調色を何にだけ使うか |
| 文字の大きさ | 本文の最小サイズ（18pt目安、大きな会場で投影するなら24pt目安）と、キーメッセージとそれ以外の差 |
| 借りるスタイル | 決まったテンプレートがない場合に借りるデザインのルール（配色・フォント・形）。構成には使わない |
| ページの強弱 | 強・中・静の並び。強いページばかり続けないが、機械的な枚数配分もしない |
| 各ページの役割 | 主張1文、根拠、情報の関係（因果・比較・並列・時間・手順）、主役と補助、表現の形 |
| 事実の出どころ | 入力資料、引用、計算した値、推測、未確認を分ける |

**10枚未満のレビュー**では、「各ページの主張1文」「ページの強弱」「色の役割」の3つだけでよい。

## 2. やめること → 代わりにすること

| 機械的にやりがちなこと | 代わりに判断すること |
|---|---|
| 3つの要素を全部同じ幅のカードにする | 比較・因果・主従のどれかを決める。主従なら大きさや位置で強弱を付ける |
| 見出し・線・数字・グラフを同じ鮮やかな色にする | 色の意味（強調・警告・状態など）と用途を決め、絞って使う |
| カードをやめた代わりに、別の飾りをたくさん使う | 余白と整列で伝わるなら、飾りを足さない |
| 名詞をそれっぽいアイコンに置き換える | アイコンに情報の役割がなければ、文字で書く |
| 全ページで大きな見出しや大きな数字を使う | 読み手の判断に効く山場だけ、大小の差を付ける |
| ページごとに背景を変える、交互に色を変える | 本文は同じ系統の背景にし、章の切り替えなど目的のあるページだけ変える |
| タイトルを「概要」「効果」「リスク」にする | 何が分かったか・なぜ必要かを、述語のある1文で書く（資料の種類に合わせて調整） |
| 主張と根拠を別のページに置く | 原則は同じページに置く。離すときは参照先を書く |
| 根拠のない効果金額や人数を足す | 計算の過程を書く。根拠が出ていないものは「要確認」にする |
| 表をそのまま全面に載せる | 一覧で比べたいなら表のまま。手順なら工程図、関係なら関係図にする |
| 余白を線・ロゴの透かし・写真で埋める | 余白は残す。写真は、実物を見せる・内容を説明するときだけ使う |
| 「リスク」「判断事項」の箱を全ページに置く | 本当に必要な項目だけ残す。判断事項は、決める対象と一致させる |
| メモや箇条書きから、いきなり完成スライドを作る | 中身を決める → ラフ → 完成の順に進め、構成は色や飾りを付ける前に確かめる |
| AIの要約をそのまま資料にする | どれが一番伝えたいことか、どれが補足かを人間が決めてから並べる |
| 調べたこと・比べた案・全部の一覧を載せる | 採った判断とその理由、確かめた事実を残す。判断を変えない情報は削る |
| 新しいスライドの初期設定のまま箇条書きにする | 主張は述語のある1文にし、関係は図・ページ分け・大きさの差で表す。一覧で比べたいときだけ箇条書きにする |
| マークダウンのような深い階層をそのまま載せる | 階層は1段までにし、それ以上はページを分けるか図にする |
| 1枚で長く話す・1枚に5行以上の文章を書く | ページを分けてテンポよく進める。文章は改行しなくて済むくらい短くする |
| 何でも中央揃えにする | 基本は左端をそろえる。中央揃えは表紙や短い1文だけのページなど、理由があるときに使う |
| 修正案を3つ並べて選ばせる | おすすめを1つ決めて理由を書く。ほかの案は、必要なときだけ短く添える |
| 判断してほしい点を最後のページにまとめる | 判断が必要な内容があるページや項目の横に置く |
| よく見る「AIっぽさ対策」の見た目をそのまま当てる | 対策の型そのものが新しい「ありがち」になる。資料の目的に合わせて理由を持って決める |

## 3. 資料の種類による例外

- **会社紹介**：社員やオフィスの写真、印象的な数字、言い切りのページは、理由があれば使ってよい。
- **IR・決裁・経営資料**：数字の検算、出典、対象期間、条件、判断の節目、施策とリスクの対応を優先する。
- **技術説明**：構成図・手順図・コード例を、読める大きさと正確さで優先する。
- **研修**：段階的な例や繰り返しが学習に役立つなら、繰り返しを残す。
- **登壇**：スライドは話を聞いてもらうための道具。読ませる文章を減らし、文字は大きく、1枚1メッセージでテンポよくページを送る。
- ブランドの決まりや、既存テンプレートで必須の仕様は、勝手に上書きしない。

## 4. 情報を増やさずに中身を強くする

- スライドのタイトルだけを上から読んで、話が通るか確かめる。
- 「問い → 答え → 根拠」のつながりを確かめる。
- 読み手が次に聞きそうな質問（根拠、費用対効果、責任者、期間、リスクの確かめ方）を挙げ、入力された情報で答えられる範囲だけ反映する。
- 合計・比率・損益分岐などは、入力された値から計算できるときだけ計算し、式・条件・単位・丸め方を残す。試算と実績を混ぜない。
- 対策は「誰が・どうする・どう確かめる」をつなげて書く。
- 最後の判断基準：**この要素を消したら、読み手が失う情報は何か**。情報も失わず、視線の誘導や構造の整理にも役立たない要素は削る候補。
