# 中身を決める（見た目の前にやること）

スライドの分かりにくさの多くは、見た目ではなく中身の整理不足から来る。中身が整理できていないと、どれだけ見た目を工夫しても伝わらない。
この手順は、色・レイアウト・図を考える**前**に行う。

## 1. 量を逆算する

発表する資料は、持ち時間からパートごとの時間を先に決め、それから中身を考える。

| パート | 時間・ページの目安 | このパートで伝えること（1文） |
|---|---|---|
| 導入 | 約 分 |  |
| パート1 | 約 分 |  |
| パート2 | 約 分 |  |
| まとめ・お願い | 約 分 |  |

- 配る・読ませる資料では、時間の代わりにページ数の目安で考える。
- 1ページで長く話す計画になっていたら、ページを分ける。

## 2. 話さないこと・載せないことを決める

詰め込んだ資料は、詰まっているのに何が言いたいか分からない。削る対象を先に言葉にする。

- 今回の読み手に関係ない話
- 知っていて当然の前提
- 別の資料や機会に回す話
- 調べた経緯、比べて却下した案（判断の根拠として必要なものを除く）

## 3. ネストした箇条書きにする

伝えたいことを、関係が分かるようにネストした箇条書きで書く。並べるだけの箇条書きにしない。

- 判断・結論の下に、その理由
- 場合分けの下に、それぞれの中身
- 主張の下に、根拠になる事実や数字

```
- 何を決めてほしいか：〇〇の導入
  - 理由：〇〇の作業に月20時間かかっている
    - 根拠：担当3人への聞き取り（11月）
  - 心配されそうな点：費用
    - 初期費用〇円、月〇円。〇か月で作業時間の削減分と同じになる（試算・式は別記）
- 確かめたこと：今の運用を変えずに入れられるか
  - 〇〇と〇〇の手順で突き合わせ、当たる点はなかった
```

既存の文章や資料を書き写すのではなく、読み手と目的から組み立て直す。
ネストにすると、項目どうしの関係（何が原因で何が起きるか、何を確かめたから何と判断したか）が見えるようになる。

## 4. 取捨選択する

各項目に次を問い、**残す／削る**と理由を並べる。

- 読み手にこれを伝える必要はあるか。読み手の理解や判断は、これがあると変わるか。
- 資料の別の場所、元データ、添付を見れば分かる内容ではないか（分かっても、判断の理解に必要なら残す）。
- 結論を支える根拠か、それとも調べた過程の実況か。

| 項目 | 残す／削る | 理由 |
|---|---|---|
|  |  |  |

- 残すのは、**採った判断とその理由**、確かめた事実。
- AIが取捨選択の案を出したときは、当然すぎる項目（「新しいから導入する」など）が残っていないか、人間がツッコミを入れる。
- 残す・削るが項目ごとに並んでいると、レビューする人が「この項目はいらない」と指して返しやすい。

## 5. 重み付けは人間が決める

- 生成AIに要約させると、どの項目も同じ重さになり、抑揚のない資料になりやすい。
- どれが一番伝えたいことか、どれは補足かを人間が決め、その順番と強弱をこのあとの手順（ラフ・設計宣言）に引き継ぐ。
- AIに任せるのは、決まった中身を見やすく並べる・図にする部分。

## 6. スライドの文章にするときの原則

- タイトル（いちばん大きい文字）で結論をはっきり言う。「概要」「効果」のような名詞だけのタイトルにしない。
- 1スライド＝1メッセージ。ページ数に制限はないので、主張が2つあれば2ページに分ける。
- 短く、シンプルに（Keep it short and simple）。体言止めや情報の凝縮を使う。
- 1枚に5行以上の文章を書かない。1文は改行しなくて済むくらい短くする。
- マークダウンのような深い階層（見出し→箇条書き→さらに箇条書き）をスライドに持ち込まない。ネストは考えるための道具で、スライドでは図・ページ分け・大きさの差で関係を表す。
- 話の流れを止めない。テーマが切り替わるときは、前の内容とのつながりが分かる一言を入れる。
- 中身のない「区切りのためだけのページ」を挟まない（章の切り替えに意味があれば残す）。
